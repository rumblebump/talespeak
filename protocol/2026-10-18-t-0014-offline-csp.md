## What changed

- `internal/pack/lint.go`: loading refuses external references in every YAML value and key and every Lua string literal, with file and line. That covers schemes, `https:host`, `javascript:`, `//host` and `www.`. Text is read the way a browser reads a URL (`\` is `/`, tabs and line breaks dropped) and the way a player reads it. It also refuses YAML tags and web files (`.css`, `.svg`, `.html`, `.js`, `.xml` and the like), which are not part of the pack format. Comments and files the engine never reads (a README) are not checked. See `docs/content-format.md`.
- `internal/server/hosts.go`: optional `TALESPEAK_HOSTS`. A Host not on the list gets 421, which stops DNS rebinding when the engine runs without Caddy. `deploy/compose.yml` sets it to `TALESPEAK_DOMAIN`.
- New tests pin what was already true: no CORS headers, the WebSocket refuses other origins, the Caddyfile has no header the engine lacks, the sandbox surface is exactly the documented one, and the script package links no `net` code.

## Findings

test-engineer (tests only) wrote edge, fuzz and Playwright tests and found these bugs:

| Bug | Fix |
| --- | --- |
| `!!binary` text passed the lint (also a security finding) | YAML tags are refused |
| A reference inside a multi-line block scalar or long string was reported on its first line | The line that holds it is reported |
| `\\host`, `/\host`, `https:\\host` and `//` split by a tab or line break passed | Text is read as a browser reads a URL |
| Story text like `//INCOMING TRANSMISSION//` was refused | `//` counts only before a host shape |
| check-web.sh let a second binding through on the line with the allowed `:src="picture.url"` | The allowed binding is removed before matching |

security-reviewer (report only): 0 critical, 0 high, 1 medium, 4 low.

| Severity | Finding | Fix |
| --- | --- | --- |
| Medium | `!!binary` let an external URL through the YAML lint | Every explicit tag is refused |
| Low | URL forms a browser parser accepts (`\`, tabs, `https:host`) | Browser reading; `https:host`, `javascript:`, `vbscript:` caught |
| Low | The file walk counted `.git`, so a pack in a git checkout was refused | Hidden folders are skipped; the loader never reads them |
| Low | DNS rebinding beats the Origin check without Caddy | `TALESPEAK_HOSTS` |
| Low | The Caddyfile parity test checked one direction | `TestCaddyfileHasNoHeaderTheEngineLacks` (test-engineer) |

security-reviewer re-review: the five fixes hold. New:

| Severity | Finding | Fix |
| --- | --- | --- |
| Low | An error snippet could be as long as the whole string (a scheme match starts at the first letter of its word) | The snippet is a window around the match's end; test with 200000 letters before `https://` |
| Low | Bare IPv4 `//10.0.0.1/a.png` no longer caught | IPv4 branch; runs of slashes (`///host`) also caught |

Not caught, and documented in `docs/content-format.md`: percent-encoded or non-ASCII host names, numeric IPs like `//3232235777`, and single-label names like `//intranet/x`. For these, the CSP blocks every load from another origin, and the client never puts pack text into a URL attribute. A full `url.Parse` check per candidate is the stronger fix when packs can be uploaded (T-0010).
