## What changed

- **T-0024** (`internal/script/table.go`, `memory.go`):
  - The memory walk now counts every slot of a table's array part, empty ones included. It also counts every key gopher-lua remembers, removed ones included, with what those keys hold. It reads gopher-lua's slices with reflect and unsafe, read only, and checks the field types at start.
  - `lua.MaxArrayIndex` is now 2^18, so `t[6e7] = true` goes to the hash part at once. Before, it filled about 1 GiB of slots.
  - `table.insert` refuses to grow a list past that.
- **T-0029** (`internal/script/timer.go`, `internal/game/push.go`, `internal/ws/ws.go`, client):
  - Lua gets `timer.start/cancel/left`, the `on_timer` hook, and `timeout` on `ui.dialog`, `ui.select` and `ui.ask` (the question returns nil once it passes).
  - Server push: `ws.Pusher`. One write lock per connection keeps pushed messages in order with the replies. A client that stops reading is disconnected once 500 messages or 256 KiB are waiting.
  - Every session field is now guarded by the world lock.
  - New `timer` and `close` messages, and `ms` on questions.
  - `WithClock` lets tests use a fake clock.
- **T-0030** (`internal/script/state.go`, `internal/game/world.go`):
  - `state.world.get/set/update`, limited to 4 MiB and 5000 keys.
  - `on_change(player, keys)` runs for the other players' current rooms, charged to their own Lua time and merged while they wait.
- Docs: `docs/lua-sandbox.md`, `docs/websocket-protocol.md`, `docs/pack-patterns.md`.

## Reviews

**test-engineer:**
- Added `internal/script/{timer,world,table_edge}_test.go`, `internal/game/{push_edge,push_fuzz}_test.go` with the `FuzzSessionOps` fuzz target, `internal/ws/{push_edge,setnotify_order}_test.go`, and seeds for `FuzzLoad`.
- Found one bug: the server called `SetNotify` on the push goroutine, so the first message could be handled before it. Fixed in `ws.go`: it is now called before the read loop. This was also the cause of a rare crash in `push_test.go`.
- Suggested that one hook's output should not disconnect a client that has read everything. Now only a client that has messages waiting can overflow.

**security-reviewer, this change:**
- Medium: one player writing world state made every other player's `on_change` run, which got round the per-address Lua budget. Fixed in two ways:
  - Deliveries are spaced at least 250 ms apart per world, and writes made meanwhile merge into one call.
  - Writing the value a key already holds is not a change.
- Low: the read-only rule of `on_change` could be bypassed through `room.go` or a timer. Fixed: `on_change` never asks a question, and the `on_enter` it moves to and the timers it starts are read-only too.
- Low: some error replies could overtake pushed messages. Fixed: `Handle` sends waiting pushed messages first.
- Low: the push queue had no byte limit. Fixed: 256 KiB.
- Low: `state.world` can carry typed text between players, which is chat for edu mode. Documented; the filter and the GM transcript come with T-0018 and T-0011.

**security-reviewer, PR #20 (T-0027):**
- Low: speaker names and labels accepted bidi controls and U+2028/2029. Fixed: the server refuses them, the client strips them from names, and names and timers are drawn with `unicode-bidi: isolate`. Emoji joiners stay allowed.
- Low: `from` is free pack text. When chat and GM messages come (T-0011), they need a look that `from` cannot copy. Noted here for that task.
