## Agent results

test-engineer (tests only): new tests for pack (about 40 error cases, FuzzLoad), script (sandbox, memory walk, FuzzLoad), game (sessions, FuzzSessionHandle) and the ws Game hooks; fixed the serve shutdown test, which the new room messages broke. Bugs found:

| Bug | Fix |
| --- | --- |
| High: ui.dialog inside a table.sort comparator or __tostring panicked out of Run and left the world lock held | Hooks run on their own goroutine and ui.dialog blocks it; game code unlocks with defer |
| High: unpack range check overflowed for huge or NaN arguments (2.5 s, 1 GiB) | Counts and positions bounded to ±2^31, NaN refused |
| High: string.format built the result before checking its size | Own string.format, length checked before each piece |
| Medium: ui.dialog inside pcall or __index was silently skipped | Fixed by the blocking dialog |
| Medium: paused hooks not counted in the state memory limit | Locals of paused hooks are walked |
| Medium: _G was shared between scripts | _G is each script's own table |
| Low: ui.dialog counted as an output | No longer counted |
| Low: a second dialog left the old number-key listener active (app.js) | One listener at a time |

security-reviewer (report only), 12 findings:

| Severity | Finding | Fix |
| --- | --- | --- |
| Critical | ui.dialog under a Go call (sort, metamethod) crashed the server; under pcall it was skipped | Blocking dialog on the hook's goroutine; panics recovered |
| High | string.gfind still ran the pattern matcher (4 s, 718 MB in one call) | Libraries built from allowlists; gfind refused |
| High | unpack/string.byte limit bypassed by integer overflow | Range-checked arguments |
| High | Format string went straight to Go's fmt (`%[1]s` reuse, `%v`/`%p` internals) | Own Lua 5.1 string.format |
| Medium | Kept memory underestimated (substrings, hash entries, paused hooks) | string.sub copies, higher estimates, paused hooks walked |
| Medium | Per-call memory budget counts the whole process | Not changed: a story hook runs well under 1 ms, so a false failure needs 32 MiB allocated elsewhere in that window; documented |
| Medium | Shared libraries writable by any script | Read-only proxies, protected metatables, rawset refuses them |
| Medium | One `..` instruction could join 250 large strings | Every `..` compiled into a size-checked call; no string over 1 MiB |
| Medium | Hooks under one world lock, no connect-rate limit | Connect rate per client address (60 at once, then 1/s, HTTP 429); one hook at a time per world noted as a known gap |
| Low | Shutdown test broken by the new messages | Fixed by the test agent |
| Low | Whole Lua error values in the log | Cut to 500 bytes and quoted |
| Low | World could be used after Close | Closed world refuses calls; Close ends paused hooks |

security-reviewer re-review of the fixes: all hold. New findings:

| Severity | Finding | Fix |
| --- | --- | --- |
| Medium | Varargs of a waiting hook are invisible to the state walk; so is a partial string.format result when a __tostring waits | Varargs refused at compile time; %s takes strings and numbers only, as in Lua 5.1 |
| Medium | table.sort without a comparator on 600k entries took 373 ms in one Go call | table.sort takes at most 20000 entries |
| Low | TestLimits/doubling_string flaky under -race | Only the timeout cases keep the short time limit |
| Low | A canceled hook could catch the error and run its full 100 ms, under the world lock | Canceled hooks get 5 ms |
| Low | Connect rate bypassed with many IPv6 addresses; map could grow past its cap | Per-client limits count IPv6 by /64; map hard-capped |

On the not-changed medium finding (per-call budget counts the whole process), the reviewer found no realistic path from network input alone once table.sort is capped.

Found while running the checks: FuzzMessage opens one connection per input and hit the new connect rate; the fuzz server now lifts it.
