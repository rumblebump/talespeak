## Findings

The security reviewer agent found 3 medium and 4 low findings. All of them are fixed:

- **M1: stale GM role.** A connection whose `Who.GM` was read before a role change could keep GM powers while the world loaded, because `Hub.RoleChanged` skips worlds that are still loading. Now `load` reads the role from `world_members` again when a store is present. A regression test is in `internal/hub/rolechanged_store_test.go`.
- **M2: audit log flooding.** Many entries of one action (such as `/go`) could push the others out of the log. Pruning is now per (world, action), with 1000 entries of each, and there is an index `audit_log_action`.
- **M3: room GM commands were not rate-limited.** A pack's GM commands broadcast a mark to the room but had no limit. They now share the limit of `/say` and `/reset`. The mark cuts the arguments at 60 bytes; the audit log keeps them whole.
- **L1: reconnecting refilled the limit.** The broadcast limit now belongs to the account and lives on the World, so connecting again does not refill it.
- **L2: on_reset charged to the wrong client.** `on_reset` during `/reset room` is now charged to the GM's client, not to each player's.
- **L3: commands table read on every call.** A room's `commands` table is now read once, when the script's top level has run, and then cached. A hook that changes it later changes nothing.
- **L4: GM lines could be faked, and the lobby showed a useless button.** The client now reads a GM's line aloud as "Game master NAME says: …" in the plain voice, never in a pack's guide voice. In edu mode, "more worlds" for a player appears only when the next page has one of their own worlds.

The test engineer agent added edge tests and fuzz tests in game, hub, script, sqlite and account. Its findings:

- **Stale GM while loading.** It reproduced the same bug as M1, which was already fixed. In worlds without a store (tests and local tools), `Who.GM` is still trusted.
- **Busy player after /reset room.** A player who is out of Lua time does not see `on_enter` until their next line, the same as when joining. This is now documented in `docs/gm-tools.md`.
- **Fixed: audit details cut by bytes.** Details could be cut inside a letter. They are now cut on a letter boundary (`store.AuditDetail`). `AuditLog` with a limit of 0 or less now returns nothing; before, SQLite read `LIMIT -1` as no limit.
- **Left as is.** `POST /api/members` with `none` for an account that is not a member answers 200 and writes an audit entry. This is harmless.
