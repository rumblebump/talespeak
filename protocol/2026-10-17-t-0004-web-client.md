## Findings

test-engineer (tests only) added edge, fuzz and e2e session tests for the script, game, pack, server, cmd and client code. It found these bugs:

| Bug | Fix |
| --- | --- |
| A refused answer to ui.ask dropped the paused hook, so the question could never be answered | ErrAnswer keeps the hook paused |
| A refused answer left the client without a question (the client had closed it) | The client cleans input like the engine and reopens the question on a refusal |
| ui.items labels skipped the YAML label rules | Same rules (one line, 1 to 100 bytes, not blank) |
| `TALESPEAK_MAX_CONNS` below the per-client default stopped the server | When unset, the per-client limit follows a lower maximum |
| parseBytes took signs and spaces | Digits and a unit only |
| e2e data directories piled up | Fixed paths, cleared by the server command |

security-reviewer (report only): 0 critical, 0 high, 2 medium, 6 low.

| Severity | Finding | Fix |
| --- | --- | --- |
| Medium | One Lua state per room: players shared script variables, so one player's typed text reached others | Every player runs their own instance of each room script (Carl chose "per player"); lasting and shared state goes to SQLite in T-0018 |
| Medium | Any address could keep the world lock busy with typed lines and clicks | Lua time budget per client address (2 s at once, then 250 ms per second); `TALESPEAK_LUA_CLIENT_RATE` and `_BURST` |
| Low | Caddy replaced the image CSP with the page CSP | `?Content-Security-Policy` in the Caddyfile keeps the engine's |
| Low | check-web.sh pipelines always exited 0, and IP and localhost URLs passed | `report` helper; IP and localhost caught |
| Low | vendor.sh trusted the values in vendor.json | Package, version, file and dest checked; `npm pack --ignore-scripts` |
| Low | A refused answer leaked a paused hook | Fixed with the test-engineer bug above |
| Low | `show = false` text still reaches the browser | Documented in lua-sandbox.md; not for secrets |
| Low | GitHub Actions pinned by tag, not SHA | Not changed: pre-existing, and Renovate `pinDigest` is configured; worth its own task |

security-reviewer re-review of those fixes:

| Severity | Finding | Fix |
| --- | --- | --- |
| High | Per-player instances all counted toward one world memory limit that latched: about 300 connections on a pack with a word list broke the world until a restart | Each instance has its own limit (`TALESPEAK_LUA_PLAYER_MEMORY`, 4 MiB); a player over it loses only their state in that room. The world limit (`TALESPEAK_LUA_STATE_MEMORY`, now 256 MiB) no longer latches: new players are told the world is full until others leave. Tests: 400 players with a 2000-word list, recovery after a full world |
| Medium | Lua budgets keyed by IPv6 /64 gave one home with a /56 hundreds of budgets; used-up budgets could be evicted to get fresh ones | Budgets count IPv6 by /48; used-up budgets are never evicted, and a new key waits while the map is full |
| Low | The client reopened the question after any error, so a script failing after an answer looped | A refused answer's error carries the question `id`; the client reopens only then (e2e test with a hook failing after ui.dialog) |
| Low | check-web.sh skipped CSS lines starting with `#` or `*`, and missed `:style`, `.src =` and `window.open` | Only `//` lines in JS and Go are exempt; style bindings and URL assignments in script are flagged. The four reported bypasses now fail the check |
| Low | Private ranges are trusted proxies by default, so a LAN device can spoof `X-Forwarded-For` | Documented in admin-limits.md: narrow `TALESPEAK_TRUSTED_PROXIES` when the port is reachable from a LAN; default unchanged |

Second security-reviewer re-review: the fixes hold, and the reviewer found nothing that escapes the per-instance walk; `r.total` never goes negative. New findings:

| Severity | Finding | Fix |
| --- | --- | --- |
| Medium | A few addresses with many connections could still fill the world on a pack with a large word list (the 222nd session got "world is full" with a 10000-word list) | Each client address (IPv6: /48) may keep at most its share, `TALESPEAK_LUA_CLIENT_MEMORY`, 64 MiB by default. That is about 55 players with a 10000-word list, so a class behind one address fits and other addresses can still join. Read-only data shared between players is noted in T-0018 as the real fix |
| Low | A walk made for the world total did not mark an instance over its own limit | Every walk breaks an instance over the limit |
| Low | A full budget map refused every new client | The budget closest to full makes room; a budget made while the map is full starts with one second's share |
